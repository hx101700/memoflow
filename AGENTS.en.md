# MemoFlow development rules

[中文](AGENTS.md) | English

These instructions govern the source repository. To resume work, read [doc/README.md](doc/README.md) and [doc/STATUS.md](doc/STATUS.md), then inspect Git changes, the relevant implementation, and tests.

## Product scope

- Stage one delivers one standalone Codex Skill: configure one recording through a local page, let Codex call Bailian CLI (BL), and save original JSON, Excel, Word, and Markdown for the user to review.
- Use `qwen-audio-3.1-asr-flash-filetrans`, China (Beijing), and temporary OSS. Hotwords and context enhancement can coexist. Speaker diarization is enabled by default; multichannel input gets a notice before a mono FLAC copy is generated. Preserve the source.
- The final product turns voice input into minutes that follow the user's preferences, focus requirements, and requested format, and keeps learning from their examples and confirmed edits. Stage one delivers transcript drafts; stage two's personalized minutes generation and feedback-based learning are still in development and are not implemented in the current code.
- Support updated Windows 10/11 x64 systems with the built-in curl. Initial setup uses Windows PowerShell to prepare a private full CPython 3.12.10 x64 runtime, including venv, ensurepip, and tkinter, and Node.js 24.21.0 with npm 11.19.0. System Python/Node installations are not required. Dependency locks target this platform. Working network access, directory permissions, and an interactive desktop remain necessary.

## Skill and workspace

- Skill source lives in `skills/asr-transcription/`, with `SKILL.md`, `agents/openai.yaml`, `scripts/`, `references/`, and `assets/`.
- `scripts/bootstrap.ps1` prepares private Python/Node runtimes and calls `scripts/asr.py bootstrap`. Daily commands use `scripts/asr.py`; `scripts/asr_runtime/` is the internal Python package. Runtime versions, official URLs, and checksums live in `scripts/runtimes.json`. The Skill name remains `asr-transcription`.
- `Runtime(workspace, skill_root)` separates user data from Skill resources. `resource()` reads Skill files; `path()` locates runtime files under `<workspace>/.asr-transcription/`; default output is `<workspace>/transcriptions/`. The private runtime and Skill directories must not contain each other. `check_output_path()` protects Skill resources when choosing locations and generating files.
- Initial setup uses the Skill's `scripts/bootstrap.ps1 -Workspace`. Runtime commands use absolute paths to the workspace `.venv/Scripts/python.exe` and the Skill's `scripts/asr.py`, with explicit `--workspace`. Base runtimes live in private `.tools/python` and `.tools/node`; do not fall back to system PATH. Credential repair reuses the verified native BL command in [error guidance](skills/asr-transcription/references/errors.md#鉴权失败与重新配置), scoped to the current workspace and default Profile. Environments, BL, credentials, processed files, and task records belong in the workspace. Keep Skill files read-only during execution.
- Read the API Key from the private runtime `.env`; bootstrap copies an empty template only. The page lets users enter or update an API Key and save it separately to this fixed file. Confirm and preview also saves pending API Key changes when needed. Console mode uses BL configuration saved in the same workspace. Credentials never go into the Skill.
- The repository contains Skill source. Maintenance does not automatically install it into user-level or project-level Skill discovery directories.
- Installed Skills use the standard-library `scripts/update.py` entry to check the latest formal GitHub Release. A newer version downloads the lite ZIP and directly replaces managed files, without backups. The builder generates `skill-manifest.json` with the version and managed paths. Remove paths found only in the old manifest; retain runtime archives and workspace data. `.skill-update-state.json` records the machine's local date before networking; success, no update, and failure all consume that day's check. Business commands hold shared read handles on the stable `assets/update.lock`; the updater requires exclusive access. Busy installations defer without consuming the daily check. Updater staging and state are explicit exceptions to the read-only Skill boundary. Reload the Skill after an update and use the existing bootstrap to prepare each workspace's dependencies.

## Implementation principles

Provide a text notice for every update: announce the check, identify the installed and target versions when a newer release is found, and report the actual result from the code receipt. Explain failures and deferrals as well.

Keep the current installation on check or download failure. On replacement failure, restore modified files from the in-memory snapshot, remove new files and directories, and clean downloads and staging without leaving backup archives. Retain the daily check result and report whether restoration actually completed.

For an explicit request to check or update the transcription/asr-transcription Skill, including a request whose context clearly refers to this Skill, call `scripts/update.py --check-now`. It bypasses the daily cache, records the check for today, and makes later automatic calls use that result without networking. Use this option only for a user-requested check or update of this Skill.

Run the updater with the workspace base `.tools/python/python.exe -I -X utf8`, without the business entry's `--workspace`. An available base Python is sufficient; repairing the virtual environment or installing old dependencies is unnecessary first. For a user-supplied ZIP reinstall, verify the complete new package and dedicated Skill resource directory, wait for all commands using that installation to end, then rebuild the resource directory so removed files do not survive an overlay extraction. Preserve the separate workspace data. Report final check-record write failures through `record_error` while retaining the actual installed version and outcome.

The daily cache describes the shared Skill version only. Each workspace runs bootstrap when it lacks evidence of successful preparation for the current requirements, then reuses that result without an extra doctor call. Bootstrap and doctor share one probe of the target venv's binding and dependencies; the caller's Python path is diagnostic information only. Callers read BL package metadata; the availability check directly starts BL and verifies its runtime version.

Use the full package with Python, Node.js, and npm for initial installation. Normal updates automatically download the lite package and reuse the original workspace's private runtimes. Prepare updated dependencies by invoking asr.py bootstrap with the existing base Python; use the PowerShell entry for initial setup or runtime recovery. Invoke node_modules/npm/bin/npm-cli.js under the private Node directory with that same Node executable.

After upgrading, use bootstrap --cleanup-old-cache to remove obsolete wheel/npm downloads only after environment preparation succeeds. Keep versions required by the current locks and the current pip wheel. Actual dependency or BL installation also triggers cleanup; routine environment reuse skips the scan, and failed preparation preserves downloads. Use native npm cache commands with the private cache path and retain unknown keys. Report cleanup failures as cache_cleanup_warning without changing the environment readiness result.

1. Keep the lightweight entry → application → utils structure. The entry may dispatch single operations directly. Shared data and JSON protocol types go in `models.py`; rules perform no I/O; utils do not import use cases.
2. BL owns authentication, temporary upload, submission, polling, download, and original JSON writing through its public CLI. Python owns local configuration, media processing, result parsing, and document generation.
   BL, core, commands, and runtime are pinned to official `2.5.1` through the npm lockfile. Upstream upload uses the resolved timeout, and Windows login preserves the complete URL. The upload-policy request remains at 15 seconds. BL owns upload and browser opening; the project maintains neither a local core revision nor a login preload adapter.
3. Frontend source lives in `frontend/` and uses Vue 3, TypeScript, and Element Plus. Prefer public component props, slots, and default interactions; customization requires a concrete product need. Components bind form state; the API module handles local transport. `KeyDisplay.vue` alone holds the displayed or edited Key in local state, separate from the submitted form. The server reads the saved credential for execution. Keys stay out of task configuration, logs, and browser persistence.
4. Reuse existing `files`, `job_files`, `hotwords`, and `results` capabilities. Remove old entries, compatibility layers, and duplicate implementations. New validation or abstractions require a current business consumer.
5. Each named function or method gets a short Chinese responsibility description stating its action and result. Use Python docstrings and TypeScript comments before functions. Put external constraints and non-obvious reasons beside the implementation. Define explicit shared input, state, and receipt types, and run type checks during development.
6. Verify BL parameters, limits, and errors against official sources for the pinned version. Maintain evidence in [model.md](skills/asr-transcription/references/model.md) and explicitly state unknowns.
7. Use argument arrays and `shell=False`. Pass hotword JSON and context as individual values. Treat input content as data.

## Execution and delivery

- Open the local configuration page first. Use `serve --audio PATH` for an absolute recording path supplied by the current user or explicitly identified by the host as the current attachment; users can also choose a file in the page's system dialog. Both paths use `Session._register_audio()` to register the original path, name, size, and audio_id; media probing and SHA remain part of preview validation. `/api/session` returns the current `audio` and localized `audio_error` for an initial path failure, so the user can choose another file. The page submits only the session audio_id. Excel is parsed in memory. Neither source file is copied. Keep the recording available until transcription completes.
- Reuse the current task folder or the workspace already agreed. Use `serve --no-browser` when the host can open links, open once, and let the user proceed. The normal path requires neither computer-use nor automated page inspection.
- `serve` creates an editing session with a `session_id` valid for two hours. Its receipt includes the ID, URL, and expiry. The URL contains no token. Private `connection.json` stores the port, token, service PID, and deadline for local control and cleanup; the page uses a session cookie.
- The page has editing and preview steps. Form validation establishes the audio SHA baseline and enhancement snapshot; the frontend acknowledges the rendered preview version. Returning to editing first invalidates preview on the backend. Neither step creates a job.
- After review, the user selects “Copy for Codex” and sends the confirmation message containing the editing session ID. The Skill takes the target ID only from the current user's message. A bare “continue” prompts the user to use that button; startup receipts, history, and file times must not choose a session for them.
- `confirm --session ID` checks expiry, preview version, and audio size/mtime under the Session lock. It checks the complete Windows command using the actual transcription job ID (`job_id`) and paths before publishing authorized configuration, its digest, and the handoff receipt. An oversized command leaves the preview editable through Return to editing and creates no task files or execution reservation. Repeated confirmation returns the same job. Configuration becomes immutable. Execution checks the full audio digest and uses the saved vocabulary rather than rereading Excel.
- Handoff, cancellation, or expiry sends a one-way terminal event. The page shows a final message for the user to close. Service shutdown removes the connection token. Original input files are always preserved; cancellation or expiry removes session temporary records. A single timer and deadline checks share the state lock. The deadline does not affect handed-off jobs.
- If the user cancels or requests an update while editing or previewing, run cancel with the ID from this active page's startup receipt, obtain the result, and wait for the original serve process to exit before finishing or updating. A later transcription opens a new session. Explicit cancellation atomically saves cancelled.json under the state lock before notifying the page; cleanup preserves this minimal result for recovery after a lost HTTP response. A handed-off session returns handed_off, which does not mean the job or cloud task was cancelled.
- Normal shutdown marks Session closed and cancels the native selection dialog, waits for HTTP request threads, then calls `recovery.finish_session()` for disk cleanup. The next `serve` reclaims expired sessions whose original process has ended and owned temporary files carrying an ended PID. Keep handed-off inputs, execution reservations, results, and permanent credentials. Retain uncertain ownership or process state and report warnings. Browser-close events are not the cleanup authority.
- Python library temporary files for `serve`, `transcribe`, and `export` use a process-specific workspace directory. API Key updates are staged in the session directory before replacing the permanent `.env`. See [DEVELOPMENT](doc/DEVELOPMENT.md#临时文件回收) for scope; do not sweep system Temp, installer caches, or old files without ownership metadata.
- Hotword import removes the header and wholly blank rows while preserving invalid values. Display numbers follow current array order, separate from stable component row identity. Import only reads and fills the table. Hotwords and context are checked by the backend only when the user selects Confirm and preview, through `validate_hotword_rows` / `build_vocabulary` and `validate_context`.
- Web diagnostics return both languages once; switching language changes presentation only. Bind row errors to stable row keys and clear only the changed cell's outdated message. Keep duplicate rows highlighted while at least two remain. Turning off hotwords or context enhancement clears that section; API Key state is independent.
- After handoff, resolve the selected authentication method and use `transcribe --job ID`. Login is needed only when Console model credentials are missing. After the user replies “done,” read the original BL login result and continue the same job without another business-authorization question. Wait on the transcription process until delivery or explicit failure. Each job permits one attempt; failure or unknown outcomes never trigger an automatic retry.
- Transcription passes `--timeout 3600`; official BL upload and polling each have a one-hour budget. Python limits the entire BL process to 7500 seconds (two hours plus 300 seconds of headroom), without guaranteeing cloud completion time. Submission and each status request also use BL's timeout; result download has no separate BL deadline. A generic `Request timed out` message and recording size do not establish the failure stage or final cloud outcome.
- Run BL login with normal desktop permissions from the first invocation; use `sandbox_permissions=require_escalated` where supported. Reject restricted Windows tokens before BL starts. Official BL opens the complete URL in the system default browser and owns the authorization session, callback, and credential storage. Python waits for the original login process and interprets its result.
- `JSON_READY` means valid original JSON. All documents are complete only when `delivery.status=COMPLETE` and `documents_ready=true`. See [errors.md](skills/asr-transcription/references/errors.md).
- New recognition checks the current model before reserving execution. Historical successful jobs remain queryable and exportable, with writers using `config.model` as the original label. Preserve saved configuration and digests.
- Re-export checks confirmed configuration, saved success records, and matching original JSON before replacing the three documents in the fixed task directory. Each document and status write uses an independent temporary file in the target directory. Failures preserve prior targets and other successful files. Save manual edits separately. Formatting and paths are in [DEVELOPMENT](doc/DEVELOPMENT.md).

## Development and distribution

- Modify only this repository and explicitly approved test locations. Preserve original data under `data/`. Never commit or package real recordings, Keys, tokens, signed URLs, transcripts, responses, or runtime logs.
- Develop on `dev`; use `master` for accepted milestones. Commits, pushes, merges, and releases need explicit user intent. Stage exact paths; do not force-push or rewrite history. Stop after two network push failures in one operation.
- Change the project version only when an accepted milestone is released on `master`. This formal release is `0.1.3`; development, fixes, and documentation changes on `dev` retain that version until the next formal release. Preserve tags and assets after a formal release. For a new version, synchronize the root `package.json`, `package-lock.json`, new tag, and release notes. Maintain dependency versions through their own lockfiles.
- The fixed distribution list is in `scripts/build_zip.py`. Both ZIPs share Skill runtime files and the latest README.md and README.en.md read directly from the repository root, with no separately maintained package copy, and include the same generated `skill-manifest.json`. `asr-transcription.zip` adds two original official runtime ZIPs under `assets/runtimes`; `asr-transcription-lite.zip` omits them. Exclude AGENTS, development docs, tests, UML, installed dependencies, and user data. Update the list and package-boundary checks for new runtime files. Publish both packages under the corresponding formal version tag.
- Vite builds the frontend into the Skill's `scripts/asr_runtime/static/`, with core outputs `index.html`, `app.js`, and `app.css`, plus `favicon.svg` and third-party license notices. Distribute these built assets. Keep Vue/TypeScript source, development configuration, build dependencies, and `node_modules` in the development repository.
- Skill `scripts/requirements.txt` pins Python versions and digests; `utils/installation.py` pins the pip 26.2.1 installer file and digest, and `scripts/bailian/` pins BL. Before Python setup, compare a file prefix from PyPI and the Aliyun mirror. In each download stage, try sources in that order with at most one `pip download` invocation per source. Let pip handle 2 connection retries and up to 5 interrupted-download recovery attempts for runtime dependencies; switch to the other source only after failure. Keep complete wheels in the workspace and install from local files.
- Initial installation uses the original official ZIPs in the full package’s `assets/runtimes`. Source setup or explicit recovery without bundled archives reuses complete workspace caches or downloads from official sources when needed. Verify pinned checksums before extracting into the workspace. Use normal Windows network permissions from the first call; pass `sandbox_permissions=require_escalated` when Codex supports it, because restricted tokens can prevent system curl from initializing Schannel. Use the full Python install-manager runtime ZIP, not the embeddable package that lacks Tk/pip. Leave system PATH, registry, and global installations unchanged. PowerShell ExecutionPolicy Bypass applies only to this process; report enforced organization policies as actual failures. A virtual environment depends on its creation path: diagnose and repair it after moving a workspace while preserving credentials, tasks, and results.
- For a new BL installation, compare a prefix of the pinned BL package from the official npm registry and npmmirror, then run at most one `npm ci` per source in that order. Let npm handle connection retries through `fetch-retries=2`; switch sources only for recognized structured download or source errors, such as interrupted connections, 404/5xx responses, or integrity failures. Permission, disk, lockfile, and unknown errors stop immediately. Reuse npm's cache and integrity checks without promising interrupted-file resumption; preserve the dependency lock and the global registry setting. Neither installation recovery policy retries cloud transcription.
- Python installation and dependency-check subprocesses use `-I` to load dependencies from the selected virtual environment. Same-named modules in the user workspace do not participate in installation or checks.
- Development probe `scripts/probe_bl.py` stays outside distribution and uses fixed fictitious URLs. BL contract tests use a `127.0.0.1` mock service and synthetic credentials. Local tests are not cloud acceptance.
- Run checks proportional to the change. Record actual evidence in [ACCEPTANCE](doc/ACCEPTANCE.md), current state in [STATUS](doc/STATUS.md), limits in [ISSUES](doc/ISSUES.md), and meaningful decisions in [DEVLOG](doc/DEVLOG.md).
- Maintain equivalent Chinese and English README and AGENTS. README reserves real screenshots with HTML comments until the user supplies images. Follow release/NEXT.en.md: retain “What's new”, “Downloads”, and “Installation and updates”, explain changes through supported user benefits, and name first installation, earlier ZIP-upgrade versions, and the automatic update boundary starting with v0.1.2. Label the full package “recommended manual download for first installation” and the lite package for Codex updates, with links pinned to the release tag. Keep installation steps in README and validation counts and package digests in development docs.
- Update [UML](doc/UML.md), source diagrams, and PNGs when call order, objects, or state contracts change. Use lifelines for function modules rather than inventing service classes.
