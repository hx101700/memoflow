## 新录音与更新分派

用户报告旧页打开后提供新录音，更新deferred却被要求提供预览编号。代码核对确认asr.py在serve整个生命周期持有共享句柄，update.py独占失败时只返回deferred且不写日检日期；附件登记本身不创建该占用。问题位于Skill对“新使用／继续旧页”的分派与“开始意图”的宽泛表述。当前修正先按本次意图决定流程：明确新录音时收尾当前对话未交接配置页，再串行更新、准备和开页；确认已核对预览时才使用编号交接。其他任务和回听页保持，更新暂缓后仍可新开填写页。

复用已有cancel、update与serve入口，未增加状态、锁、占用扫描或自动终止。扩展打包集成用例验证实际服务退出、更新可执行、新附件保持与不提前建job；独立只读推演新附件／继续确认／其他目录占用三个场景，均沿上述边界分派。现场完整工具记录仍缺失，后续以真实用户复测补齐。

## 发现与处理

| 发现 | 处理与证据 |
| --- | --- |
| UI已删除等待操作，回听取消接口仍有旧调用 | 同步删除前端picker状态、取消方法、等待文案及ReviewSession.cancel_picker、HTTP路由；系统窗口的取消结果仍通过原选择请求返回 |
| 导出过的稿件再编辑，旧导出提示遮住保存进度 | 同一区域内先显示保存中，再显示需重新导出；延迟保存的浏览器用例验证优先级 |
| 导出期间播放控件全部被禁用 | 播放可用性与文件导出操作分开，选择/导出期间仍能暂停；浏览器用例实际点击验证 |
| 点击正文切换输入后光标位置丢失 | 用浏览器文字定位接口取得字符偏移并交给textarea，实际鼠标点击检查光标位于正文中 |
| 音频重选失败后修复入口被错误提示遮住 | 录音仍不可用时在同一错误区域保留重选按钮，错误路径浏览器检查通过 |
| 控件间距、按钮尺寸、播放与改动反馈不统一 | 复用page-shell/AppHeader及Element Plus默认尺寸；顶部操作等宽等高，播放蓝色/改动绿色，阅读区上下24px留白，内部卡片上下8px，正文14px |

## 保留的边界

- 原转写配置页仍调用/api/cancel-picker和共享PathPicker.cancel，不能随回听清理一起删除。
- picker_id仍是实际选择请求传给共享PathPicker的编号；删除的是回听页面额外取消流程，未重写公共选择器。
- 草稿revision、原句基线、按句时间、独立校验导出记录分别服务保存冲突、重置、播放与文件交付；没有新增后端修改导航接口。
- 页面在场连接用于最后关页收尾，复用真实连接EOF与10秒刷新宽限，没有客户端心跳或云端轮询。
