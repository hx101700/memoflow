## 发布前复核

### v0.1.2发布文案与执行一致性

发布说明的收益对应现有改动：轻量包减少运行时重复下载，复用工作目录环境，官方BL处理上传期限与Windows授权链接，环境探针定位绑定和依赖问题，升级后清理旧下载。没有根据这些改动编造耗时或识别准确率提升。

安装与更新说明明确v0.1.0/v0.1.1采用ZIP升级，v0.1.2起提供自动更新入口，未来获取更高正式版本。更新器只读取GitHub版本元资料、包内manifest和受管资源，Release正文不参与判断。用户可选择后续Codex更新或提供ZIP；两条入口继续复用已有安装流程。正常使用时的日检要求、并发保护和各工作目录依赖准备均未改变，UML02/09仍对应实现。此核对按用户要求仅推理，未增加或重跑自动更新测试。

### bootstrap、doctor与更新路径

首次安装使用完整版和PowerShell准备运行时；后续轻量更新由已有基础Python执行更新器及bootstrap，Node与npm仍来自同一工作目录。正常更新不重复准备运行时，bootstrap成功后直接继续；doctor只用于诊断。双语README、Skill和图02/09已同步。

实际探针发现doctor原先比较当前调用者的base_prefix，可能遗漏目标venv绑定到其他Python。现由目标venv的同一个隔离子进程检查平台、绑定和依赖加载，bootstrap与doctor共用；缺包与解释器无法启动分别报告。删除bootstrap的独立绑定探针及BL检查中重复的包元信息读取。

共享Skill的日检结果不能证明每个工作目录均已升级。Skill现要求没有当前工作目录准备成功证据时，先bootstrap再打开页面，避免把依赖版本错误拖到任务执行占用以后。没有新增环境版本注册表或第二套安装器。

升级成功后清理本工作目录的旧wheel及npm下载键，保留当前依赖锁对应版本、当前pip和业务数据。官方/镜像键可能共享旧内容，npm批量clean会因内容已删提前结束；已用真实缓存复现，改为逐键clean后一次verify回收失效索引。当前缓存仍可读取由真实npm合约验证；普通已就绪环境不扫描缓存。

### 更新器与发行资源

逐段阅读当前更新入口、业务入口、打包器、Skill及引用资料，并按安装、检查、覆盖、回退、依赖准备和继续执行核对UML。独立审查及探针确认并修复了以下问题：

- 更新入口无需workspace参数且只依赖基础Python；原文“所有命令传workspace”和使用venv的示例会引导错误调用或先装旧依赖，现已限定业务入口并改用基础Python。
- 直接覆盖解压会留下旧BL登录适配及core归档；人工ZIP更新现要求完整核对新包后重建专用资源目录，工作目录独立保留。使用真实v0.1.1资源复现并验证旧文件已移除。
- 新文件及清单已发布后，最终日检记录写入失败原本会误报更新失败；现以record_error附带说明，保留真实安装版本和成功结果，缓存可由已发布清单识别完成状态。
- replaced_files、removed_files和needs_reload只有测试消费者，现已删除，避免日内缓存反复输出整份文件路径；Skill直接根据status指导后续动作。

官方BL 2.4.0的鉴权、上传、轮询和JSON落盘职责保持完整，不重新实现其能力。当前更新功能没有引入差分服务、下载重试循环、PID登记或第二套依赖安装器。独立行为核对确认：主动更新仅指向本Skill；登录完成继续原任务；其他Skill的更新不会误触发本入口。

## Skill 每日更新

新增的 `scripts/update.py` 独立处理每日版本检查、轻量 ZIP 下载与安装目录覆盖，不导入待替换的业务模块；标准库依赖使它能在业务环境准备前执行。`asr.py` 仅增加导入前的共享读取保护，业务调用保持原样。构建器生成版本和受管路径清单，更新删除旧清单独有文件，业务依赖仍由原 bootstrap 准备。自动更新没有逐文件差分协议、备份目录、后台定时器或第二套 pip/npm 安装器。

主动入口只响应明确指向语音转写 Skill 的请求，`--check-now` 共用原检查方法并记录当天结果。更新进度由工具输出、Codex文字告知。正文中断按实际 `IncompleteRead` 转为失败回执。覆盖失败通过内存原内容恢复文件、移除新增文件与目录，正常清理暂存；回退完成后旧版本可继续用，当天不自动重查。恢复结果不明时不声称回退成功。

## 附件入口与文案复核

新增入口只把明确提供的本机录音路径传给现有网页会话，初始附件与原生窗口共用 `_register_audio()`。该方法登记路径、类型、扩展名和大小；媒体读取及完整 SHA 沿用预览用例。路径失败记录双语 audio_error，页面保持编辑；成功替换在原状态锁内清错并作废旧预览。

前端从 `/api/session` 恢复录音选择或显示路径错误，沿用预览、返回修改与交接协议。检查了语言切换、刷新及迟到窗口结果的消费者，未增加新的执行状态。独立代理按真实附件请求选择 Skill、启动网页并等待用户填写；源码复核与浏览器实测相互印证，见 ACCEPTANCE。

文案修改集中在预览版标签、导入与上传用词、确认消息、API Key 术语及官方资料链接。README 的价值说明以 Qwen 3.1 官方能力和现有文件化执行为依据，学习能力保持后续目标。依赖、安装框架和云端识别流程沿用原有实现。

## 独立运行时复核

首次安装由一个 PowerShell 入口准备工作目录内的固定 Python/Node 运行时，读取官方归档及摘要后进入既有 bootstrap。更新复用已有基础Python直接进入同一个依赖安装入口。

完整包的运行时归档只读使用，正常轻量更新保留已安装运行时。源码安装或显式恢复缺少归档时，PowerShell才走缓存和官方下载；解压前核对摘要，解压完成后发布目标目录。Windows PowerShell 显式加载当前宿主自带工具模块，解决从其他宿主启动时继承模块路径导致 Get-FileHash 缺失的实测问题。

所有 Python、Node 和 BL 调用都使用工作目录内的确定路径；命令长度预检与执行阶段检查分别保护交接和实际启动。venv 检查验证基础解释器绑定，避免把其他环境误报为当前独立环境。业务协议、凭据、一次执行约束与前端流程保持现行实现。

完整回归与双包边界测试的结果独立记录，不把历史验收数字当作当前安装器的证据。

v0.1.1 的全新中文目录安装进一步发现 `ensurepip` 内部子进程只继承隔离模式，输出仍使用 Windows 本地编码。当前按该命令的实际编码读取，再写入统一的 UTF-8 日志；普通 pip 继续显式使用 UTF-8。修正覆盖实际标准库调用，不修改 ensurepip 实现或系统编码设置。

## Skill 写法

按本机 skill-creator 的要求，入口使用明确的 name/description；触发范围限定为录音转写、百炼凭据配置和已有任务重导。正文给出正常操作、认证分支、交付与停止条件，详细安装参数、恢复方法和官方依据按需读取 references。`agents/openai.yaml` 是标准的可选展示元数据。

参考方向是具有固定脚本或外部 CLI 的任务型 Skill：[OpenAI transcribe](https://github.com/openai/skills/blob/main/skills/.curated/transcribe/SKILL.md) 的明确输入与交付边界，以及 [OpenAI gh-fix-ci](https://github.com/openai/skills/blob/main/skills/.curated/gh-fix-ci/SKILL.md) 的 CLI 复用和状态判断。保留本项目已确定的网页确认与 BL 行为，不照搬其他任务的审批步骤。
