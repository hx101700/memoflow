## 已修正的问题

| 问题及证据 | 当前修改 |
| --- | --- |
| BL 安装固定一个来源并关闭 npm 下载重试；切换 npm 来源需要与本机安装错误区分 | 比较两个固定来源后调用原生 npm ci，结构化下载错误才切第二源，每源最多一个进程。版本、锁、缓存校验均由 npm 保持；11 项真实 npm 本机合约验证有限换源、完整性拒绝、缓存复用与本机错误停止。响应头等待较长的实证也修正了共享采样的起始时点 |
| 检查期间仍可修改表单，需要修订计数、丢弃结果和额外返回编辑请求；导入与预览可能互相竞争 | 检查期间保留整份表单和摘要，只禁用修改。成功进入本次预览，失败恢复填写；删除主表单修订计数、自动撤销旧预览及相应状态文案。凭据异步读取的版本仍有迟到响应消费者，予以保留 |
| 2000 条各自合法的长热词可生成超过 Windows 32767 个 UTF-16 单元的命令；原检查发生在不可变任务与执行占用之后 | 交接写盘前用真实任务编号和路径检查完整参数；超长保留预览供修改，不生成任务文件。交接与执行复用同一构造和检查，不截断词条，也不假设 BL 支持热词文件参数 |
| Windows venv 启动器 PID 与实际 Python worker 不同；中断安装、诊断超时或取消窗口可能只结束启动器 | 安装与有限本机命令共用 `stop_process_tree()`，只处理本次 `Popen`。Tk helper 直接使用基础 Python，使窗口取消指向实际进程。回归持有真实 worker 句柄核实退出，未扫描整机进程 |
| 浏览器测试失败清理只停止测试服务的启动器 | 测试收尾按本次创建的 PID 结束进程树，确认退出后再删除合成目录；未触碰用户验收服务 |
| 主流程变更后仍有闲置字段、文案和说明 | 删除未消费的 Excel 大小字段、旧字段别名和未使用翻译项；同步“原文件引用”“独立保存 Key”“检查期间禁用表单”和命令长度边界 |
| UML 的返回修改缺少再次校验循环，单独配置凭据与识别阶段的边界不够明确 | 图 03 补齐反复填写与预览、确认失败及取消/到期分支；图 04 让只保存 Key 的操作结束于取消编辑会话，转写以已交接任务为前提。源稿和 PNG 同步 |

此前用户共同验收发现的词表重复组逐删、旧诊断残留、侧栏首屏遮挡和不可用页重复提示仍在回归范围。表头行号、热词、权重居中，热词正文左对齐；没有为外观调整复制 Element Plus 的默认交互。

## 保留的设计及用途

| 边界 | 保留理由 |
| --- | --- |
| 轻量分层 | Python 入口分派、application 编排、utils 提供能力；utils 不反向导入用例。Session 和 PathPicker 持有真实生命周期，无状态操作保持模块函数 |
| 单一 Skill 与 BL 工具 | 当前只有一个完整转写任务；公开 CLI 调用集中在 bailian，不新增通用代理、工具注册或独立 BL Skill。BL 继续负责鉴权、临时上传、提交、轮询、下载及原始 JSON |
| 编辑会话与任务分开 | 反复填写和预览不产生任务；用户提供 session_id 后，代码才交接唯一不可变 job。裸“继续”不能代选会话，编号也不替代请求令牌 |
| 预览就绪和状态锁 | 页面实际展示后登记版本；返回修改、确认和到期在同一 Session 锁内互斥，避免接管旧预览。没有数据库、心跳或云端状态轮询 |
| 交接回执与执行占用 | config.json 是交接完成标记；重复确认恢复同一任务。独占 execution 目录限制每个任务的一次本地尝试，失败不自动上传 |
| 三处输入检查 | 预览建立原音频事实与摘要；交接仅核对 size/mtime；执行前核对完整摘要。Excel 只在内存导入，执行读取已确认的 vocabulary |
| 凭据分离 | Key 存在工作目录，预览配置与任务只记录认证方式。API Key 模式直接执行；控制台模式仅在状态未知时查 BL，缺少模型凭据才登录；在线有效性由实际 BL 调用判断 |
| 共享规则与诊断 | 热词和上下文只在确认并预览时调用后端规则。双语错误一次返回；稳定行键维护错误归属，显示序号随数组重排。编辑仅移除过时诊断，不重新实现规则 |
| 文件生命周期 | 音频直接引用原路径，仅合并声道时产生处理文件。按会话记录和 PID 回收确定归属的暂存；原文件、正式凭据、任务和结果保留 |
| 共享结果与输出 | results 统一解析，三个 writer 使用同一 Transcript；重导复用原 JSON 和固定任务路径。输入、配置、JSON 摘要各有实际消费者，成品不另算无消费者的摘要 |
| 安装恢复 | Python/npm 共用前缀采样；pip 负责有限续传，npm 负责有限请求重试与缓存。来源选择只用于工作目录安装，不改全局源，也不增加识别重试 |
| 发行单一来源 | 固定清单包含 Skill、构建产物、运行资料及根目录双语 README；排除开发 doc、AGENTS、UML、测试、环境与用户数据 |

## Skill 写法

按本机 skill-creator 的要求，入口使用明确的 name/description；触发范围限定为录音转写、百炼凭据配置和已有任务重导。正文给出正常操作、认证分支、交付与停止条件，详细安装参数、恢复方法和官方依据按需读取 references。`agents/openai.yaml` 是标准的可选展示元数据。

参考方向是具有固定脚本或外部 CLI 的任务型 Skill：[OpenAI transcribe](https://github.com/openai/skills/blob/main/skills/.curated/transcribe/SKILL.md) 的明确输入与交付边界，以及 [OpenAI gh-fix-ci](https://github.com/openai/skills/blob/main/skills/.curated/gh-fix-ci/SKILL.md) 的 CLI 复用和状态判断。保留本项目已确定的网页确认与 BL 行为，不照搬其他任务的审批步骤。

当前指令让用户在网页填写并复制确认消息；缺少编号时仅补充编号，已有开始意图不重复询问。必要登录后继续同一任务，已有可用环境不反复安装或运行 doctor。只保存 Key 可以无录音结束；重导不重新认证或识别。官方 `quick_validate.py` 已通过，正常与恢复路径另由源码核对、本机测试及新对话验收分别证明。

本轮没有新增生产依赖或通用框架。尚未覆盖的新环境完整使用、真实云端识别及 Office 视觉，不因本机测试通过而标为完成。
