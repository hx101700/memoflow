## 关键复现实验

### BL 安装换源与共享采样

使用 Node 24.19.0、npm 11.12.1 和合成包验证生产 `_install_bailian()`。保留真实 npm 进程、标准流和隔离目录，只在故障测试中将 npm 重试次数改为 0、请求期限改为 300ms，以缩短等待；生产命令仍使用 `fetch-retries=2`。普通包和 scope 包均按所选 registry 请求，锁文件、固定版本与 integrity 保持不变。

503、连接中断、响应前超时、接收正文后停顿及错误摘要分别产生 E503、ECONNRESET、FETCH_ERROR、EIDLETIMEOUT、EINTEGRITY，均按结构化结果换源。两源摘要错误只启动两个 npm 进程后停止；锁冲突 EUSAGE、来源拒绝 E403、本机文件占用 EBUSY 不换源。首源已完成的包在第二次 ci 中由 npm 缓存复用，备用源只收到未成功包的请求。磁盘空间不足按原生错误码测试停止分支，没有实际填满磁盘。

两个公开来源的 BL 2.1.0 元数据摘要先与仓库锁匹配，再分别使用独立新目录、独立缓存进行完整依赖安装并运行版本入口；没有复用已安装 Skill 或执行登录/识别。安装成功后临时目录自动清理。速度仅表示本次环境，不能保证将来下载同样快。

真实采样发现连接/响应头耗时超过 5 秒时，旧循环会在读正文前结束并返回零吞吐。现把正文采样窗口起点放到响应就绪时，评分仍包含连接等待；本机慢响应头回归通过，真实两个来源均得到非零采样值。Python 与 npm 共用此修正，不新增下载器。

### 检查期间的编辑与状态

浏览器以 Promise 暂停真实校验请求，确认表单、侧栏和表格节点保留，输入、行键、上下文与 Key 不被重置；修改、导入和选择入口暂时禁用。释放请求后只执行一次校验和预览就绪登记，没有额外返回编辑请求。失败时恢复原表单，可在原位置修正。

热词只在“确认并预览”调用后端规则。61 行场景检查内部滚动和末尾错误定位，2000 行场景检查导入与编辑。三个或四个重复词逐删时，剩至少两条继续标红；剩一条才清除重复提示。坏 Excel 导入保留原数据和旧错误，显式再次检查替换上一轮诊断。

### Windows 进程回收

无网络合成 worker 在启动后输出真实 PID，测试先持有其 Windows 进程句柄，再触发取消、日志失败或超时。修复前可复现启动器结束、worker 仍存活；修复后对应句柄均确认退出。安装中断与有限命令超时复用同一停止函数；Tk helper 直接使用基础解释器。正常退出不调用停止工具。

浏览器测试的收尾也改为结束其自建服务进程树，确认退出后再删除合成目录。早期失败用例只保留了启动器标识，未尝试扫描或批量结束无法确认归属的 Python 进程；最终回归采用修正后的收尾。用户验收服务和 ui-* 目录保持原样。

### 热词命令的可执行性

2000 条各自合法的长热词可通过模型规则，却使完整 Windows 命令超过 32767 个 UTF-16 单元。测试验证交接写盘前即拒绝：会话及预览保留，没有任务配置、回执或执行占用；返回修改后可以再次预览和交接。原音频与合并声道路径均使用实际任务目录；交接检查与执行准备采用相同参数构造。

固定 BL 2.1.0 源码核对表明即时热词参数接收 JSON 文本；没有添加猜测的文件或标准输入参数。API Key 分支的本机 BL 合约使用隔离控制台配置及合成 Key，确认无需登录；模拟 401 不自动重试。请求仅到 127.0.0.1。
